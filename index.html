Totales comparados

Los bytes de cabecera son una estimación didáctica (MQTT ≈ 2 B, AMQP ≈ 8 B, HTTP ≈ 250 B por mensaje). El handshake TLS de HTTP se repite en cada petición porque no mantiene conexión.

Registro de mensajes

¿Qué es cada cosa y para qué sirve?

MQTT · puerto 8883

Protocolo de publicación/suscripción muy ligero. El dispositivo mantiene un socket abierto (KeepAlive) y publica en el tópico devices/<id>/messages/events/. Con qos=1 espera confirmación (PUBACK) del hub.

Para qué: sensores a batería, ESP32/ESP8266, redes celulares con cobro por datos.

AMQP · puerto 5671

Estándar empresarial (ISO/IEC 19464). Permite multiplexar varias sesiones (telemetría, comandos C2D, Device Twin) sobre una sola conexión, con liquidación de mensajes (at-least-once / exactly-once). Tu script usa el SDK de Azure, que habla AMQP/TLS.

Para qué: gateways industriales, aplicaciones críticas, flujos bidireccionales masivos.

HTTPS REST · puerto 443

Modelo petición/respuesta sin estado: cada medición es un POST a /devices/<id>/messages/events con un token SAS (HMAC-SHA256 con la clave del dispositivo + expiración) en la cabecera. Un 204 indica éxito.

Para qué: dispositivos que despiertan rara vez, sistemas legacy, redes que solo dejan salir por 443.

DPS (Device Provisioning Service)

Los tres scripts empiezan registrándose en DPS con SCOPE_ID, DEVICE_ID y clave simétrica. DPS responde con el IoT Hub asignado al que luego se conecta cada protocolo. Evita codificar el hostname a mano.

Variables de telemetría

Temperatura (°C): alerta > 26 °C. Humedad (%): alerta > 60 %. Voltaje (V): nivel de batería/alimentación del nodo (~3.1–3.3 V); alerta < 3.15 V. Los valores en rojo superan su umbral.

Por qué importan las diferencias

El mismo dato (~60 bytes) cuesta muy distinto: MQTT casi no añade cabecera, AMQP poco, y HTTP más de 200 bytes más un handshake TLS cada vez. Eso se traduce en ancho de banda y energía: por eso MQTT gana en batería y HTTP solo conviene con envíos muy espaciados.

Cuándo elegir cada uno

MQTT: nodos de bajo consumo, microcontroladores con poca RAM/Flash, redes móviles con tarifa por volumen.
AMQP: pasarelas industriales, almacenamiento intermedio, misión crítica con colas y alta fiabilidad.
HTTP/HTTPS: envíos muy esporádicos (p. ej. un reporte diario), sistemas legacy, entornos restringidos a tráfico web 443.
